# Архитектура MOVAŬ

Трёхслойка в solution: **Domain** (сущности) → **Application** (сценарии) → **Infrastructure** (EF, Redis, JWT) + хост **Api**. Снаружи три процесса: **gateway** (YARP :8000), **core** (HTTP + PostGIS), **realtime** (SignalR). Auth, кошелёк и GIS не выносим: эскро и заявки — одна транзакция в Postgres. Отдельной БД на сервис нет — это не 8 микросервисов.

Внутри слоёв один тип — один файл: `Entities/User.cs`, enum в `Enums/`, DTO по папкам домена, EF `IEntityTypeConfiguration` на сущность, HTTP-маршруты по группам. Это раскладка модульного монолита, не CQRS и не MediatR.

## Сейчас

```
браузер / Expo  →  gateway :8000
                    ├─ /api/v1/*     → core :8001  → PostgreSQL 16+PostGIS
                    └─ /hubs/chat    → realtime :8002
                                         ↕ Redis pub/sub movau.realtime
                                      Redis (смена, трек)
```

Домены внутри core:

- `auth` — регистрация, JWT
- `users` — профили, роли (client, executor, volunteer, …)
- `help_requests` — заявки с `Geography(POINT, 4326)`; лента `ST_DWithin` и фильтр `category`
- `offers` — отклик исполнителя, назначение автором, start/complete
- `messages` — HTTP-чат заявки в core. Realtime: SignalR `/hubs/chat` на отдельном процессе, пуш через Redis `movau.realtime`
- `reviews` — взаимные оценки после `completed`; карма профиля = сумма полученных баллов, среднее и число оценок считаются при чтении (колонок на `users` нет). Публично: `GET /users/{id}/reviews`
- `wallet` — демо-эскроу: `wallets`, `wallet_holds` (held/released/refunded), `wallet_txns`. Холд на accept, выплата на complete, возврат на cancel. «Дарма» без холда. Профиль показывает баланс, холды и проводки
- `identity` — паспорт/ID + селфи в очереди модератора (`identity_verifications`). Лицо сверяет человек, не нейросеть. Создавать и брать заявки (в том числе дарму) можно только с `verified`
- `notifications` — колокол и `/inbox`: `href` на заявку (`#chat`), SignalR `notification` в `user:{id}`
- `phone` — демо-OTP `123456` в Redis `phone:{user}`, `phone_verified_at`; номер второй стороне заявки, не в публичной карточке
- `track` — живая точка исполнителя по заявке, Redis `track:{requestId}` TTL 90 с, SignalR `location`. ETA при ping: OSRM, иначе 4 м/с; пробок в OSM нет
- `admin` — консоль: разделы, поиск, пагинация, список людей с выдачей ролей, карточка, журнал аудита (`actor_email`, код события, объект). Матрица: модератор выдаёт executor/volunteer; admin — ещё business/moderator/analyst. Роль admin через API не выдаётся
- `disputes` — спор сторон заявки после назначения; модератор закрывает
- `business` — кабинет партнёра: список своих заявок и пакет 2–8 точек с lat/lng на каждую, лимит 20 активных
- `analyst` — кабинет `/analyst`: снимок, воронка created→taken→completed, конверсия, теплослой `cells`, точки `points`, CTR подбора ranked vs random
- `match` — `GET /requests/{id}/matches`: люди на смене в 5 км, баллы 0–100 = дистанция до 50 + навык 30 + карма до 20; топ-3 ranked помечаются «AI рекомендует»; A/B по id заявки (ranked/random), журнал `match_events`
- `heroes` — волонтёры по карме
- демо-сид: `*@movau.test` / `movau123`

Клиенты: веб — основной UI; `mobile/` — Expo MVP на тот же `/api/v1`.

## На защите

- Матчинг — скоринг 0–100 (дистанция, навык, карма), не нейросеть. Топ-3 ranked несут значок «AI рекомендует». A/B: чётный первый байт id → ranked, нечётный → случайный порядок того же пула. CTR в `/analyst`.
- Трек — Redis + SignalR. ETA считается на ping через OSRM по графу дорог. **Live-пробок в OpenStreetMap нет** (это Google/Yandex). Нет ответа OSRM — скорость 4 м/с.
- Эскро — `wallet_holds` / `wallet_txns` в Postgres: создана → оплачена (заморожено) → исполнена → выплачено. **Hyperledger Fabric — следующий этап**, неизменяемый лог холдов, не замена MVP.
- Личность сверяет модератор, не AI. Кольца на профиле: личность, карма (до 20), средняя оценка.
